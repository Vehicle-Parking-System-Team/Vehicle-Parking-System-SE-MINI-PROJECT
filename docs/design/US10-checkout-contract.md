# US-10 atomic checkout and slot release

This contract reconciles the existing US-19 checkout with the fee integration
required by US-10 (#30)
alongside US-12 (#32). It reuses ParkingRecord, the configured ParkingRate and
the existing slot-state services. Payment, invoices, receipts and a checkout
screen remain separate work; this PR does not close their user stories.

## Endpoint

`POST /api/parking/check-out/` requires an active Admin or Operator account:

```json
{"registration_number": "KA01AB1234"}
```

The plate is normalized using the existing vehicle helper. Only that request
field is accepted; clients cannot supply prices, timestamps, record status,
slot IDs or payment status. A successful checkout returns HTTP 200 with the
existing parking-record fields plus:

```json
{
  "status": "COMPLETED",
  "duration_seconds": 3660,
  "billable_hours": 2,
  "fee_amount": "80.00",
  "currency": "INR",
  "hourly_rate_snapshot": "40.00",
  "grace_period_minutes_snapshot": 15,
  "vehicle_type_snapshot": "Compact"
}
```

`check_out_time` is generated by the server and returned with the record.
Decimal amounts are strings. `duration_seconds` is an integer count of whole
seconds across record/check-in/checkout responses, or NULL for an active
record. Fee calculation retains microsecond precision independently of this
display value, so one hour plus one microsecond still incurs two billable hours.
The check-in operator is retained; checkout does not overwrite that attribution.
The existing US-19 integer-duration contract and public availability
field allowlist are retained. One checkout service and route serve both
US-19 behavior and US-10 fee processing; there is no parallel checkout path.

| Failure | Status |
| --- | --- |
| Missing/malformed plate or extra request fields | 400 |
| Anonymous / inactive or unauthorized role | 401 / 403 |
| Unknown vehicle, no active record, repeated checkout | 404 |
| Missing/invalid tariff, negative duration, inconsistent active record or slot, amount overflow | 409 |
| Unexpected processing failure | Sanitized 500 |

All failures use the shared `{error, code, details}` envelope.

## Fee policy

The check-in vehicle-class snapshot selects its configured ParkingRate at checkout.
Legacy records without that snapshot fall back to the vehicle's current class.
This matches the US-20 history integration merged in PR #75 and preserves the
class under which the session began when a vehicle profile is later edited.
No default rate is invented if it is missing. The configured grace period
applies inclusively: elapsed time <= grace is free. Otherwise the **full elapsed
duration**, without subtracting grace, is rounded up to whole hours and
multiplied by the hourly rate. There is no additional vehicle multiplier or
automatic use of `penalty_fee`. That existing setting is unchanged and remains
outside this ordinary-fee workflow.

For INR 40/hour and a 15-minute grace period:

| Duration | Fee |
| --- | --- |
| 15 minutes | INR 0.00 |
| 15 minutes and 1 microsecond | INR 40.00 |
| Exactly 1 hour | INR 40.00 |
| 61 minutes | INR 80.00 |

Integer microsecond arithmetic preserves grace/hour boundaries; Decimal handles
money. Negative/non-finite/sub-cent hourly rates and unsupported totals are
rejected before any record changes. The maximum persisted fee is
INR 999999999999.99. Elapsed time uses timezone-aware timestamps, not local
calendar-day grouping.

## Transaction and persistence

`operations.services.check_out_vehicle` owns one transaction. It locks the
vehicle first, matching check-in, then its active record. It reads the configured
tariff once without a row lock: a single SELECT captures the rate/grace tuple and the transaction saves
those values as immutable snapshots. A concurrent tariff edit therefore need
not wait for checkout, and cannot change the already selected fee inputs. After
validation/calculation, it saves the fee, class/rate/grace snapshots and exit
timestamp and marks the record COMPLETED. It then calls `release_slot`, which
locks the zone before the slot. The record, snapshots and Occupied → Available
transition commit together. Failure at any step rolls them all back.

The active-record guard sees the completed record in this transaction and
permits release. Other requests cannot see the uncommitted fee/completion
writes. Concurrent checkout attempts are
serialized by the vehicle lock; only one completes, and the other returns 404.

`0003_checkout_fee_snapshots` adds four nullable fields to ParkingRecord without
rewriting existing rows. Historical charges remain NULL, including on old
completed records; they are not guessed from today's rates. A later tariff or
vehicle-class edit does not rewrite saved snapshots or fees. Duration and
billable hours are derived from the saved timestamps and grace snapshot.

Slot release follows successful **fee processing**, without asserting payment
settlement. Checkout creates no invoice, records no payment, and never returns
a Paid status. This defines the US-10 release boundary; the SAD's broader
payment/receipt sequence remains outside this PR.
